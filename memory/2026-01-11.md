## Key Learnings

### Pirsch API
- Uses **website ID** (`zy1bBvG1lv`), not domain name
- Endpoint: `/api/v1/statistics/overview?id=<website_id>`
- Can filter by path: `?path=/blog/slug`
- OAuth client must be linked to domain in Pirsch dashboard

### Twitter OAuth 1.0a
- v2 endpoints need User Context (Bearer token), not App-Only
- v1.1 endpoints work with OAuth 1.0a signatures
- Used `twitter-api-v2` package for clean signing

### Content Pipeline
